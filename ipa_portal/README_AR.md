# WolFox — لوحة IPA الخاصة 3.0.0

صفحة PHP عربية باتجاه RTL وتصميم أزرق يناسب الهاتف. تستقبل ملف IPA أو رابط HTTPS مباشرًا، وتتيح إضافة حتى ثماني مكتبات dylib اختيارية. عند النجاح تعرض بيانات التطبيق وبصمة SHA-256 ورابط تنزيل خاصًا، مع سجل وحذف للملفات.

## ما الذي تفعله؟

- بدون مكتبات: تفحص ZIP ثم تعيد الملف نفسه، دون تغيير توقيعه أو أي بايت فيه.
- مع مكتبات: تتحقق من Mach-O، وتنسخ المكتبات إلى `Frameworks/WolFoxInject` وتضيف أوامر `LC_LOAD_DYLIB` إلى الملف التنفيذي الرئيسي، وتزيل أمر توقيعه القديم ومجلدات `_CodeSignature`، ثم تبني IPA جديدًا. لا تُنفّذ أي مكتبة على الخادم.
- **ناتج الدمج يحتاج إعادة توقيع التطبيق والمكتبات قبل التثبيت. لا تحتوي اللوحة خدمة توقيع أو شهادة Apple.** نجاح الدمج لا يثبت توافق المكتبة وقت التشغيل؛ تظهر اعتمادياتها في النتيجة. المكتبات التي تعتمد على Substrate أو ملفات خارجية تحتاج بيئتها واعتمادياتها المناسبة.
- الدمج يدعم Mach-O ‏64-bit arm64 وUniversal الذي تتكون جميع شرائحه من arm64/arm64e. تُرفض التطبيقات المشفّرة، والشرائح الأخرى، والترويسات التي لا تملك مساحة آمنة. لا يوجد فك تشفير أو تجاوز حماية.
- الملفات الاختيارية المقبولة حاليًا هي `.dylib` فقط؛ لا يوجد تثبيت DEB أو دمج frameworks/resources تلقائي. أسماء المكتبات إنجليزية دون مسافات، وتبقى الأسماء نفسها داخل التطبيق. يُرفض الحقن المكرر عند تطابق اسم المكتبة أو بصمتها أو هوية LC_ID_DYLIB مع مكتبة موجودة داخل IPA أو ضمن الملفات المختارة. تغيير الاسم وحده لا يسمح بحقن K7GPS الموجود أصلًا مرة ثانية.

## متطلبات التشغيل

خادم Linux مع PHP 8.2 أو أحدث، وPython 3.11 أو أحدث، و`proc_open` وsessions مفعلة. لا يلزم Composer أو قاعدة بيانات أو إضافات Python. استخدم HTTPS، وذاكرة متاحة للعامل نحو 1.5 جيجابايت، وقرصًا فارغًا لا يقل عن 3 جيجابايت للعملية. التخزين الافتراضي 10 جيجابايت، وبحد 20 نتيجة. تُعالج عملية واحدة في كل مرة.

يلزم أن تسمح الاستضافة بعملية Python تستمر حتى 280 ثانية. إذا كانت الاستضافة المشتركة تمنع `proc_open` أو Python، فلن تعمل وظيفة الدمج عليها؛ استخدم VPS أو خطة تسمح بهذه المتطلبات. الـPHP وحده لا يكفي للدمج في هذه الحزمة.

## التثبيت

1. ارفع مجلد `ipa_portal` إلى مسار خاص مثل `/home/USER/ipa_portal`.
2. اجعل **Document Root** للنطاق أو النطاق الفرعي `/home/USER/ipa_portal/public`. لا تجعل جذر المشروع كله مكشوفًا عبر الويب. إذا لم تسمح اللوحة بتغيير جذر الموقع، ضع محتويات `public` في `public_html` وبقية المجلدات خارجه، ثم صحّح مساري `require` في `public_html/index.php` إلى `../ipa_portal/src/bootstrap.php` و`../ipa_portal/src/view.php`.
3. في نسخة المصدر من GitHub، أنشئ حسابك من الطرفية: `php bin/setup.php`. في حزمة التسليم الخاصة يأتي `config.local.php` مجهزًا بالحساب المطلوب؛ لا ترفع هذا الملف إلى GitHub. لتغيير الحساب: `php bin/setup.php --reset`.
4. يجب أن يملك مستخدم PHP صلاحية قراءة `config.local.php` وكتابة `storage`؛ اجعل الملف `600` والمجلد `700` وملكيتهما لمستخدم الخدمة. لا تستخدم صلاحيات 777. اضبط مسار Python في `config.local.php` إذا اختلف عن `/usr/bin/python3`.
5. فعّل HTTPS وافتح النطاق. الإعداد الافتراضي يرفض HTTP. إذا كان TLS ينتهي عند reverse proxy موثوق، اضبط `HTTPS=on` في إعداد خادم PHP الخاص بذلك المضيف؛ لا تعتمد على ترويسة يرسلها الزائر مباشرة.
6. اضبط PHP كما في `public/.user.ini`: رفع 512M، ومجموع طلب 800M، و9 ملفات، ومهلة 310 ثوانٍ. اضبط حد الرفع في Apache/Nginx/مزود البروكسي أيضًا. بعض الخطط تفرض حدًا أقل لا يمكن رفعه بملف ini.
7. أضف مهمة تنظيف كل ساعة: `0 * * * * /usr/bin/php /home/USER/ipa_portal/bin/cleanup.php`. الروابط تنتهي بعد 24 ساعة. يمنع التنزيل بعد الانتهاء حتى قبل التنظيف، ويجري تنظيف إضافي عند الرفع.

لا يوجد مسار مثبت داخل الروابط: تُبنى تلقائيًا على النطاق والمسار الحاليين. يمكن نقل اللوحة إلى نطاق فرعي دون تعديل JavaScript. الرابط مباشر للتنزيل لكنه **يتطلب جلسة دخول**؛ بعد تسجيل الدخول يعاد فتح الرابط المطلوب. لا يوجد رابط عام يتجاوز تسجيل الدخول.

## مثال Nginx (عدّل النطاق ومسار PHP-FPM)

```nginx
server {
    listen 443 ssl;
    server_name ipa.example.com;
    # أضف ssl_certificate و ssl_certificate_key من شهادتك.
    root /home/USER/ipa_portal/public;
    index index.php;
    client_max_body_size 800m;
    location / { try_files $uri $uri/ =404; }
    location ~ /\. { deny all; }
    location = /index.php {
        include fastcgi_params;
        fastcgi_param SCRIPT_FILENAME $document_root/index.php;
        fastcgi_param HTTPS on;
        fastcgi_pass unix:/run/php/php8.3-fpm.sock;
        fastcgi_read_timeout 330s;
    }
    location ~ \.php$ { return 404; }
}
```

في Apache يلزم السماح بإعدادات `.htaccess` المرفقة. ملفات حماية Apache لا تحمي Nginx؛ جذر `public` الصحيح ضروري في الحالتين.

## حماية البيانات والحدود

الحساب محفوظ كبصمة `password_hash`، مع تجديد الجلسة وHttpOnly وSameSite=Strict وCSRF ورفض ثماني محاولات دخول خاطئة خلال 15 دقيقة على مستوى حساب الإدارة. قائمة الملفات والتنزيل والحذف كلها خلف الدخول. الملفات خارج جذر الموقع، مع حد للحجم وعدد الملفات وحجم ZIP بعد الفك ورفض الروابط الرمزية والمسارات الخطرة. جلب الروابط يتحقق من كل تحويل ويثبّت الاتصال بعنوان IP عام مع تحقق TLS لمنع الوصول إلى الشبكة الداخلية وإعادة ربط DNS.

حد IPA ‏512 ميجابايت، والمحتوى بعد الفك 2 جيجابايت، والملف التنفيذي 256 ميجابايت. تُرفض بعض الحزم السليمة التي تستخدم روابط رمزية أو معماريات قديمة، بدل معالجتها بطريقة غير مدعومة. تنتهي الجلسة بعد ساعة دون طلبات. الملفات الأصلية والمكتبات المؤقتة تُحذف بعد نجاح المعالجة؛ النتائج تبقى حتى الحذف أو الانتهاء. لا تُنشر كلمات المرور أو ملفات IPA في مستودع المصدر.

## التحقق

```sh
python3 -m unittest discover -s tests -p 'test_*.py' -v
find . -name '*.php' -not -name config.local.php -exec php -l {} \;
```

اختبارات HTTP تنشئ نسخة مؤقتة وحساب اختبار مستقل وتختبر الدخول والحماية والرفع والدمج والتنزيل والحذف. لا تستخدم حسابك الحقيقي ولا تخزّن تطبيقاتك في الاختبارات.

مرجع PHP لاستدعاء العامل بمصفوفة معاملات دون shell: [proc_open](https://www.php.net/manual/en/function.proc-open.php)، ومرجع [خصائص جلسة الدخول](https://www.php.net/manual/en/function.session-set-cookie-params.php).
